# デイリータスク管理アプリ 開発ロードマップ Ver.1.0

作成日：2026-11-16

## 1. 目的
実装と確認をどの順番で進めるかを定める。進め方は開発規約の「1機能・1変更 → 検証 → 次の変更」を前提とし、土台（日付判定）を先に固めてから、見た目と便利機能を積み上げる。

## 2. 開発原則
- 各フェーズは「完了条件」を満たしてから次へ進む
- フェーズの途中で仕様にない機能を足さない。必要になったら仕様書を更新してから取り込む
- フェーズごとに進捗記録（07）へ記録し、Gitへ保存する

## 3. フェーズ

### Phase 0：プロジェクト土台
- Xcodeプロジェクト作成（SwiftUI＋SwiftData、iOS 17+）。App層のフォルダは既存プロジェクトの `DailyTasksGame/` とし、`App/` フォルダは新設しない（2026-11-16決定）
- テンプレートの `Item` モデルとその一覧画面は Phase 0 で削除する。SwiftDataの接続確認は Phase 1 の正式モデル（Game等）で行う（2026-11-16決定）
- ローカルパッケージ `Packages/AppCore`（本体ターゲット＋テストターゲット）を作成し、アプリから参照できるようにする
- `scripts/verify.sh`（AppCoreの単体テストを実行する入口）を用意する
- 本文書一式（docs/）とAGENTS.mdをリポジトリへ配置
- Gitリポジトリ初期化、.gitignore、初回コミット
- 空のタブ画面（今日／統計／設定）が起動する状態
- **完了条件**：Simulatorと実機で空アプリが起動する

### Phase 1：データモデルとゲーム・タスク管理
- Game / TaskItem / CompletionRecord のモデル定義
- ゲームの追加・編集・削除・休止切替・並び替え
- タスクの追加・編集・削除・有効切替・並び替え
- **完了条件**：登録したゲームとタスクが、アプリ再起動後も保持される（実機確認）

### Phase 2：ゲーム日判定とホーム画面（中核）
- AppCore内に GameDayCalculator（ゲーム日・ウィークリー期間の判定）を実装し、境界ケースの単体テストを通す（実行は `scripts/verify.sh`）
- ホーム画面：ゲーム別グループ表示、チェック切替、残数・リセットまでの残り時間表示
- リセット跨ぎで表示が新しいゲーム日に切り替わる
- **完了条件**：仕様書 §4 のテストが全通過。端末時刻をずらした確認で、リセット前後で表示が正しく切り替わる（Simulator確認）

### Phase 3：ストリークとゲーム詳細
- 達成日・ストリーク計算（仕様書 §8）
- ゲーム詳細画面：ストリーク表示、月カレンダー（達成／一部／未達成）
- **完了条件**：過去データを用意した状態で、ストリークとカレンダーが仕様どおり表示される

### Phase 4：通知
- 通知許可リクエストと設定画面（オン／オフ、リードタイム）
- 未完了があるゲームへのリセット前通知のスケジュール（状態変更時に再登録）
- **完了条件**：実機で、リセット前に通知が届くこと／完了済みゲームには届かないことを確認

### Phase 5：ウィジェット
- App GroupでSwiftDataストアを共有
- small / medium ウィジェット（残り件数とゲーム別内訳）
- リセット時刻でのタイムライン更新
- **完了条件**：実機のホーム画面で、アプリの状態と一致した表示になる

### Phase 6：統計
- 週ごとの達成率グラフ（Charts）、ゲーム別フィルタ
- **完了条件**：数週間分のデータで達成率が正しく計算・表示される

### Phase 7：仕上げ
- 空状態・エラー表示の整備、ダークモード・Dynamic Type確認
- アイコン、アプリ名の確定
- 全体の回帰確認（登録→チェック→リセット→通知→ウィジェット→統計）
- **完了条件**：開発規約 §17 の「完成の定義」を満たし、本人が正式採用する

## 4. 統合ルール
- 作業はフェーズごとのブランチで行い、完了条件を満たしたらPull Requestで `main` へ統合する
- 統合前に進捗記録（07）を更新する

## 5. フェーズ移行ルール
- 完了条件を満たさないまま次フェーズへ進まない。問題が残る場合は進捗記録に残件として明記し、本人が判断する
- 仕様変更が必要になったら、その場で実装せず、仕様書を更新してから該当フェーズへ差し戻す

## 6. 将来の検討事項（今は導入しない）
- GitHub Actionsによる最小CI：AppCoreの単体テストだけをPRで自動実行する。PR運用が定着してから導入し、実行入口はローカルと同じ `scripts/verify.sh` に揃える
- 検証手順のCodex Skill（`.agents/skills/`）への切り出し：手順が固まり、繰り返し使うようになってから検討する

## 7. 進捗管理
- 現在のフェーズと状態は進捗記録（07_進捗記録.md）の「現在の状況」に一元化する
- このロードマップ自体の変更（フェーズ追加・順序変更）は、本人の決定で更新し、版を上げる
